# Procera website

The public site for Procera: static HTML, CSS and inline SVG with a small amount of vanilla JS
(about 10 KB, no frameworks, no CDNs), generated by a small Python script (standard library only,
no packages to install).

## Build

```bash
python3 site/build.py
```

This runs `site/scripts/build-data.py` (reads the tracker, writes `site/data/tracker.json`),
renders `site/src/pages/*.html` with the partials in `site/src/partials/`, and writes the site
to `site/dist/` with `sitemap.xml`, `robots.txt` and the assets.

Canonical and Open Graph URLs use `SITE_URL` (default `https://casualoffice.github.io/Procera`):

```bash
SITE_URL=https://procera.example.org python3 site/build.py
```

## Preview

Internal links are relative, so you can open `site/dist/index.html` directly, or serve it:

```bash
python3 -m http.server -d site/dist 8000   # http://localhost:8000
```

The one exception is `404.html`: GitHub Pages serves it for a missing path at any depth, so the
build rewrites its links to absolute `SITE_URL` links.

## Layout

| Path | What |
|---|---|
| `build.py` | The generator. `{{ token args }}` in pages and partials expand to the functions in `TOKENS`. |
| `src/pages/` | One file per page. A comment at the top holds `title`, `description` and `nav`. |
| `docs/guides/*.md` | The self-hosting guides. `get-started.html` renders them with `{{ guide name }}` through the small Markdown converter in `build.py` (headings, lists, tables, code, links; links between guides become in-page anchors). Edit the guides, not the page. |
| `src/partials/` | `head`, `header`, `footer`, and `story` (the animated hero, built from product UI fragments). |
| `src/content.py` | Features, user flows, comparison rows, personas, the core loop, screenshot alt text and crops. |
| `src/home.py` | Home-page sections (proof numbers, loop, pillars, tour, personas, tamper demo, timeline). |
| `src/illustrations.py` | Original inline-SVG illustrations: pillars, personas, diagrams. One stroke and fill system, styled by `illus.css`, built around the logo's ribbon geometry. |
| `assets/css/*.css` | `site` (base), `story`, `home`, `illus`, `pages` (inner pages and all motion). Concatenated into one `site.css` at build time. |
| `assets/js/*.js` | `site` (theme toggle) and `motion` (reveals, counters, hero loop, tour frame, tabs, tamper demo). Concatenated into one `site.js`. |
| `scripts/build-data.py` | Parses `scripts/build_tracker.py` with `ast` (never imports or edits it) into `data/tracker.json`. |
| `scripts/review.mjs` | Serves-over-HTTP review: every page at 1440 and 390 px, light and dark, plus reduced motion and a 360 px reflow pass; checks links, anchors, alt text, overflow, console errors, keyboard tabs and wording. |
| `scripts/webp.py` | Offline (needs Pillow): writes the WebP twin of each screenshot. Outputs are committed; the build only links them. |
| `scripts/og-image.mjs` | Renders `assets/og.png` (1200×630) from the brand banner SVG. |
| `assets/screens/` | Real product screenshots (2×), light and dark, PNG plus WebP. |

## Motion and accessibility

Everything moves only when the visitor hasn't asked for reduced motion: `motion.js` sets
`html.motion`, and every motion rule sits behind it. Without JS, or with reduced motion, pages show
their final state (the hero markup ships finished, counters print the real number) and nothing
loops. The hero loop pauses off screen, in a hidden tab and from its Pause button. The core-loop
line uses a CSS view timeline where supported and draws once on reveal elsewhere. Persona tabs
follow the APG tabs pattern (roving tabindex, arrow keys, Home and End).
| `assets/fonts/` | Geist and Geist Mono (SIL OFL 1.1, see `OFL.txt`), self-hosted. |

Logos and the favicon are copied from `assets/brand/vector/` at build time; brand assets are not
covered by the Apache licence.

## Where statuses come from

Nothing on the site types a status by hand:

- **Features** list the tracker epics they depend on (`src/content.py`). All done means
  *Available now*; any done or in progress means *In progress*; none started means
  *Planned · release, month* (the earliest release among its epics). The one exception is
  starter templates, which have no core epic and cite the browser test that proves them.
- **User flows** name their E2E test ids, and the build fails if an id isn't found in `e2e/packs`.
- **Roadmap** is generated from the tracker's releases and epics, with its last-updated date
  taken from the last commit to `scripts/build_tracker.py`.

So after a tracker update, rebuild the site and the pages follow.

## Review

Playwright is not a dependency of the site. Use the copy installed for the E2E suite:

```bash
SITE_URL=http://127.0.0.1:8765 python3 site/build.py      # so the 404 page's absolute links resolve locally
python3 -m http.server -d site/dist 8765 --bind 127.0.0.1 &
PLAYWRIGHT=e2e/node_modules/playwright node site/scripts/review.mjs /tmp/procera-site-review http://127.0.0.1:8765
python3 site/build.py                                     # rebuild with the real SITE_URL afterwards
PLAYWRIGHT=e2e/node_modules/playwright node site/scripts/og-image.mjs   # only when the banner changes
```

## Hosting on GitHub Pages

The output is plain files, so any static host works. For GitHub Pages:

1. Build with the final URL, e.g. `SITE_URL=https://casualoffice.github.io/Procera python3 site/build.py`.
2. Publish `site/dist/`, either from a workflow that runs the build and uses
   `actions/upload-pages-artifact` + `actions/deploy-pages`, or by pushing `site/dist/` to a
   `gh-pages` branch. A `.nojekyll` file is included so files are served as-is.
3. For a custom domain, add a `CNAME` file to `site/dist/` and set `SITE_URL` to match.

`.github/workflows/site.yml` runs `python3 site/build.py` and publishes `site/dist/` to GitHub Pages on every push to `main`.
